# ARVELIS AI — Smart Entry post-merge QA

Основание: реальный iPhone/WebView запуск после merge PR №7.

## Подтверждено реальным запуском

- Smart Entry отображает утверждённый логотип ARVELIS AI;
- персональное имя подхватывается на loading-screen;
- измеримый progress показывает реальные завершённые задачи подготовки;
- локальные данные восстанавливаются;
- приложение открывается без белого экрана;
- mobile navigation скрывается при открытой клавиатуре.

## Исправления текущего patch

### 1. Один full-screen loader

После завершения критической подготовки full-screen Smart Entry должен сразу передать управление приложению. Повторный full-screen `Открываем раздел` после 100% не допускается.

Core-компоненты App Layout, стартовый экран и Chat возвращаются из реальной preload-фазы и используются напрямую после её завершения. `Suspense` остаётся только для второстепенных разделов.

Если History/Profile/System States ещё не готовы, fallback отображается внутри App Layout и не заменяет весь интерфейс повторной заставкой.

### 2. Chat + iPhone keyboard

При фокусе в textarea:

- нижняя навигация скрывается;
- не используется конкурирующий `position: fixed` поверх существующей sticky-модели;
- `visualViewport` resize/scroll инициирует прокрутку composer в доступную область;
- helper `LOCAL PREVIEW · ...` временно скрывается;
- после закрытия клавиатуры обычная навигация и layout восстанавливаются.

### 3. Компактный preview-status

Новые system messages используют короткий текст:

`Сохранено в локальном preview. AI пока не подключён.`

Точно известные старые длинные служебные сообщения нормализуются в эту форму при чтении localStorage. Пользовательские сообщения не изменяются.

## Проверка после будущего merge

1. Replit → Git → Pull → Run.
2. Welcome → `Открыть ARVELIS AI`.
3. Убедиться, что после измеримого loader нет второго full-screen `Открываем раздел`.
4. Открыть History/Profile сразу после входа: при редкой холодной догрузке допускается только небольшой inline-state внутри приложения.
5. Открыть Chat и поставить курсор в поле сообщения.
6. Проверить позицию composer с открытой клавиатурой, скрытие mobile nav и отсутствие скачков layout.
7. Отправить новое сообщение: system-status должен быть коротким.
8. Перезагрузить страницу и открыть старый диалог: известные старые длинные system-status должны нормализоваться, пользовательские сообщения должны остаться без изменений.
