# ARVELIS AI — Smart Entry post-merge QA

Основание: реальный iPhone/WebView запуск после merge PR №7.

## Подтверждено реальным запуском

- Smart Entry отображает утверждённый логотип ARVELIS AI;
- персональное имя подхватывается на loading-screen;
- измеримый progress показывает реальные завершённые задачи подготовки;
- локальные данные восстанавливаются;
- приложение открывается без белого экрана;
- mobile navigation скрывается при открытой клавиатуре.

## Исправления текущего patch

### 1. Один full-screen loader

После завершения критической подготовки full-screen Smart Entry должен сразу передать управление приложению. Повторный full-screen `Открываем раздел` после 100% не допускается.

Core-компоненты App Layout, стартовый экран и Chat возвращаются из реальной preload-фазы и используются напрямую после её завершения. `Suspense` остаётся только для второстепенных разделов.

Если History/Profile/System States ещё не готовы, fallback отображается внутри App Layout и не заменяет весь интерфейс повторной заставкой.

### 2. Реальные этапы Smart Entry

Loader показывает три фактические задачи:

- `Интерфейс` — загружены App Layout и стартовый экран;
- `Диалог` — загружен Chat module;
- `Данные` — подготовлено локальное preview-state.

Чек/готовое состояние этапа появляется только после завершения соответствующего Promise. Порядок может отличаться на разных устройствах — это нормально, задачи выполняются параллельно.

После завершения всех трёх задач статус становится `ARVELIS AI готов` и показывает 100%. Перед передачей управления приложению браузеру даётся один следующий кадр для отрисовки этого фактического ready-state. Искусственного таймера или минимальной длительности loader нет.

### 3. Мягкий background warmup

History, Profile и System States не конкурируют с первым экраном за CPU одновременно. После входа второстепенные чанки прогреваются последовательно:

- через `requestIdleCallback`, если браузер его поддерживает;
- в Safari fallback запускается после двух кадров первого экрана.

Ошибка фонового warmup не должна блокировать основной старт.

### 4. Возвратная персонализация и race safety

- если отображаемое имя уже сохранено локально, обычный `Открыть ARVELIS AI` должен подхватить его к финальному ready-state и затем на стартовом экране;
- `Продолжить с именем` должен предзаполнить ранее сохранённое имя;
- повторный быстрый запуск/retry не должен позволять старому async-запуску перезаписать новый progress/state.

### 5. Chat + iPhone keyboard

При фокусе в textarea:

- нижняя навигация скрывается;
- не используется конкурирующий `position: fixed` поверх существующей sticky-модели;
- `visualViewport` resize/scroll инициирует прокрутку composer в доступную область;
- helper `LOCAL PREVIEW · ...` временно скрывается;
- после закрытия клавиатуры обычная навигация и layout восстанавливаются.

Экранная entrance-анимация больше не оставляет постоянный `transform: translateY(0)` после завершения. Это предотвращает создание лишнего containing block, который мог нарушать fixed/modal/keyboard UI в Safari.

### 6. Компактный preview-status

Новый диалог получает одно короткое системное уведомление:

`Сохранено в локальном preview. AI пока не подключён.`

Последующие пользовательские сообщения в том же диалоге больше не создают новый дубликат служебного статуса. При чтении localStorage точно известные старые длинные статусы преобразуются в короткую форму, а повторные одинаковые preview-status внутри одного диалога схлопываются до одного. Пользовательские сообщения не изменяются.

### 7. Защита от зависшей критической загрузки

Core interface и Chat dynamic import имеют защитный timeout 20 секунд. Это не влияет на реальный процент и не создаёт искусственную длительность loader. Если обязательный chunk действительно завис, Smart Entry переходит в retry-state вместо бесконечного ожидания.

Retry не удаляет локальные preview-данные.

### 8. Короткий экран и landscape

Smart Entry больше не полагается на `overflow: hidden`: при очень коротком viewport содержимое остаётся доступным. Для mobile/landscape уменьшаются только размеры и отступы loading-композиции; утверждённая структура логотипа не меняется.

## Проверка после будущего merge

1. Replit → Git → Pull → Run.
2. Welcome → `Открыть ARVELIS AI`.
3. Проверить три реальные стадии `Интерфейс / Диалог / Данные`.
4. Проверить финальный статус `ARVELIS AI готов · 100%`.
5. Убедиться, что после него нет второго full-screen `Открываем раздел`.
6. Повторно открыть приложение с уже сохранённым именем: финальный ready-state и Home должны обратиться по имени.
7. Открыть `Продолжить с именем`: сохранённое имя должно быть предзаполнено.
8. Открыть History/Profile сразу после входа: при редкой холодной догрузке допускается только небольшой inline-state внутри приложения.
9. Открыть Chat и поставить курсор в поле сообщения.
10. Проверить позицию composer с открытой клавиатурой, скрытие mobile nav и отсутствие скачков layout.
11. Создать новый диалог и отправить ещё 2–3 сообщения: preview-status должен остаться только один.
12. Перезагрузить страницу и открыть старый диалог: известные старые длинные/повторные system-status должны нормализоваться, пользовательские сообщения должны остаться без изменений.
13. Повернуть телефон в landscape на Smart Entry: композиция не должна обрезаться, при необходимости страница должна оставаться прокручиваемой.
14. При искусственно плохой сети/отказе chunk загрузка не должна висеть бесконечно: после защитного интервала должен появиться retry-state.
