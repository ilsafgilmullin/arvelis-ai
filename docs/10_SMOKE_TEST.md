# ARVELIS AI — Smoke Test Preview QA Candidate

Этот сценарий предназначен для контрольного запуска после merge в `main` и Pull в Replit.

## Перед тестом

- Replit подключён к `ilsafgilmullin/arvelis-ai`;
- активная ветка — `main`;
- локальных незакоммиченных изменений нет;
- Replit Agent не требуется.

## 1. Запуск

1. Выполнить Pull в Git-разделе Replit.
2. Нажать Run.
3. Дождаться установки npm-зависимостей и старта Vite.
4. Открыть Web Preview.

Ожидаемый результат: открывается welcome screen ARVELIS AI без горизонтального переполнения и ошибок загрузки.

## 2. Welcome

Проверить:

- утверждённый золотой знак ARVELIS;
- надпись ARVELIS / AI / `INTELLIGENCE. PRECISION. RESULTS.`;
- строгий графитово-золотой стиль;
- маркировку Product Preview;
- обе кнопки перехода.

## 3. Demo Access

1. Открыть экран входа.
2. Убедиться, что форма **не просит email, пароль, токен или другой секрет**.
3. Ввести отображаемое имя или оставить поле пустым.
4. Продолжить.

Ожидаемый результат: открывается workspace; реальная учётная запись не создаётся; используется только локальное отображаемое имя.

## 4. Workspace

Проверить:

- приветствие с локальным именем;
- composer принимает текст;
- счётчик символов меняется;
- пустой запрос отправить нельзя;
- быстрые сценарии `Работа`, `Учёба`, `Решение` открывают локальный диалог;
- длинный текст и длинная строка без пробелов не создают горизонтальный overflow.

Дополнительно: прокрутить Workspace вниз, перейти в другой раздел и вернуться. Workspace должен открыться с начала страницы, а не с прежней позиции прокрутки.

## 5. Chat

1. Создать новый диалог.
2. Ввести короткое сообщение и отправить.
3. Ввести многострочное/длинное сообщение.
4. Вставить длинный URL или строку без пробелов.
5. Убедиться, что textarea растёт по содержимому до разумного предела.
6. Отправить несколько сообщений подряд.
7. Переключиться на другой раздел и вернуться.

Ожидаемый результат:

- сообщения остаются в текущем demo-сеансе;
- при доступном localStorage они переживают обычную перезагрузку;
- после добавления сообщения интерфейс прокручивается к последнему сообщению;
- система честно сообщает, что AI не подключён;
- никаких фальшивых AI-ответов не генерируется;
- длинный URL/слово переносится и не расширяет страницу.

На desktop: Enter отправляет, Shift+Enter переносит строку.

На телефоне: при фокусе в input/textarea нижняя навигация должна временно скрываться, освобождая место экранной клавиатуре, и возвращаться после снятия фокуса.

## 6. History

Проверить:

- новый диалог появился в истории;
- поиск находит его по заголовку/сообщению;
- открытие строки возвращает в нужный диалог;
- при нажатии удаления сначала появляется окно подтверждения;
- `Отмена` сохраняет диалог;
- подтверждение удаляет только выбранный локальный диалог;
- длинные названия не ломают ширину строки.

Для confirm-dialog дополнительно проверить на desktop:

- `Escape` закрывает окно;
- `Tab` и `Shift+Tab` не выводят фокус за пределы окна;
- после закрытия фокус возвращается на кнопку, открывшую подтверждение.

## 7. Profile

Проверить:

- изменение имени применяется;
- при доступном localStorage после перезагрузки имя остаётся;
- длинное имя до допустимого лимита не ломает layout;
- `Сбросить demo-данные` сначала показывает подтверждение;
- `Отмена` не меняет данные;
- подтверждение сброса восстанавливает стартовое состояние.

## 8. Offline

После загрузки preview временно отключить сеть на устройстве.

Ожидаемый результат: интерфейс показывает offline banner; уже загруженная локальная часть приложения остаётся доступна и не выдаёт offline-режим за работу AI.

## 9. Local storage failure

Обычному пользователю не требуется специально ломать хранилище. Критерий реализации:

- если localStorage недоступен, переполнен или demo-состояние превышает безопасный локальный бюджет, приложение продолжает работать в текущей сессии;
- сверху появляется предупреждение, что изменения могут исчезнуть после перезагрузки;
- приложение не должно молча удалять старые диалоги для освобождения места;
- последняя корректно сохранённая версия в localStorage не должна перезаписываться заведомо некорректным/слишком большим состоянием.

## 10. System States

Через Profile открыть `Состояния интерфейса` и проверить вкладки:

- loading;
- empty;
- error;
- offline;
- limit.

Все состояния должны быть явно обозначены как demo. На этом внутреннем экране не должно быть кнопок, которые выглядят рабочими, но ничего не делают.

## 11. Runtime fallback

Обычный пользователь не должен специально ломать приложение для этой проверки. Критерий реализации: если React-дерево получает необработанную runtime-ошибку, вместо пустого белого экрана должен появиться брендированный экран `INTERFACE ERROR` с кнопкой перезагрузки.

## 12. iPhone portrait

Проверить:

- нет горизонтальной прокрутки;
- верхняя часть не залезает под Dynamic Island/notch;
- нижняя навигация учитывает safe area;
- touch targets удобно нажимаются;
- клавиатура не закрывает поле ввода;
- mobile navigation скрывается во время ввода и возвращается после закрытия клавиатуры;
- фокус на input/textarea не вызывает нежелательный zoom Safari;
- длинный текст не ломает ширину.

## 13. iPhone landscape

Повернуть устройство горизонтально и проверить Workspace, Chat, History и Profile.

Ожидаемый результат:

- телефон не переключается в desktop-sidebar только из-за большей CSS-ширины;
- используется компактная нижняя навигация;
- учитываются левый/правый safe-area inset;
- composer и клавиатура не перекрываются навигацией;
- нет горизонтального overflow.

## 14. Узкий экран

На ширине около 320–360 px проверить Welcome, Workspace, History и Profile.

Ожидаемый результат: заголовки, DEMO-chip, кнопки и нижняя навигация не выходят за границы экрана и остаются читаемыми.

## 15. Desktop / tablet

На desktop проверить:

- sidebar остаётся фиксированной рабочей навигацией;
- контент не растягивается чрезмерно;
- Workspace имеет двухзонную композицию на широком экране;
- на промежуточной ширине примерно 781–1180 px Workspace безопасно перестраивается в одну колонку и не создаёт overflow;
- confirm-dialog доступен с клавиатуры;
- нижняя mobile navigation не отображается на обычном desktop.

## Что считать ошибкой

- белый/пустой экран;
- npm/Vite error в Run;
- бесконечная загрузка;
- горизонтальный overflow;
- новый раздел открывается в случайной старой позиции прокрутки;
- кнопка визуально нажимается, но не выполняет описанное локальное действие;
- demo/mock отображается как настоящий AI/backend;
- demo-вход просит реальные учётные секреты;
- интерфейс утверждает, что данные сохранены, когда localStorage недоступен;
- данные молча удаляются из-за внутреннего demo-лимита;
- удаление или полный сброс происходят без подтверждения;
- confirm-dialog позволяет фокусу уйти за окно;
- нижняя навигация перекрывает composer/клавиатуру;
- landscape на телефоне неожиданно показывает desktop-sidebar.

## Отложенная инфраструктурная задача

`package-lock.json` пока отсутствует. Не создавать его вручную. Он должен быть получен только реальной установкой npm-зависимостей в доверенном окружении и затем проверен перед коммитом.

При обнаружении ошибки достаточно прислать скриншот экрана и, если доступен, скрин Console — Shell не требуется.
