# ARVELIS AI — Smoke Test Preview v0.2

Этот сценарий предназначен для запуска после merge в `main` и Pull в Replit.

## Перед тестом

- Replit подключён к `ilsafgilmullin/arvelis-ai`;
- активная ветка — `main`;
- локальных незакоммиченных изменений нет;
- Replit Agent не требуется.

## 1. Запуск

1. Выполнить Pull в Git-разделе Replit.
2. Нажать Run.
3. Дождаться установки npm-зависимостей и старта Vite.
4. Открыть Web Preview.

Ожидаемый результат: открывается welcome screen ARVELIS AI без горизонтального переполнения и ошибок загрузки.

## 2. Welcome

Проверить:

- утверждённый золотой знак ARVELIS;
- надпись ARVELIS / AI / `INTELLIGENCE. PRECISION. RESULTS.`;
- строгий графитово-золотой стиль;
- маркировку Product Preview;
- обе кнопки перехода.

## 3. Demo Access

1. Открыть экран входа.
2. Убедиться, что форма **не просит email, пароль, токен или другой секрет**.
3. Ввести отображаемое имя или оставить поле пустым.
4. Продолжить.

Ожидаемый результат: открывается workspace; реальная учётная запись не создаётся; сохраняется только локальное отображаемое имя.

## 4. Workspace

Проверить:

- приветствие с локальным именем;
- composer принимает текст;
- счётчик символов меняется;
- пустой запрос отправить нельзя;
- быстрые сценарии `Работа`, `Учёба`, `Решение` открывают локальный диалог;
- длинный текст не создаёт горизонтальный overflow.

## 5. Chat

1. Создать новый диалог.
2. Ввести короткое сообщение и отправить.
3. Ввести многострочное/длинное сообщение.
4. Убедиться, что textarea растёт по содержимому до разумного предела.
5. Отправить несколько сообщений подряд.
6. Переключиться на другой раздел и вернуться.

Ожидаемый результат:

- сообщения остаются;
- после добавления сообщения интерфейс прокручивается к последнему сообщению;
- система честно сообщает, что AI не подключён;
- никаких фальшивых AI-ответов не генерируется.

На desktop: Enter отправляет, Shift+Enter переносит строку.

На телефоне: при фокусе в composer нижняя навигация не должна перекрывать экранную клавиатуру.

## 6. History

Проверить:

- новый диалог появился в истории;
- поиск находит его по заголовку/сообщению;
- открытие строки возвращает в нужный диалог;
- при нажатии удаления сначала появляется окно подтверждения;
- `Отмена` сохраняет диалог;
- подтверждение удаляет только выбранный локальный диалог.

## 7. Profile

Проверить:

- изменение имени сохраняется;
- после перезагрузки страницы имя остаётся;
- `Сбросить demo-данные` сначала показывает подтверждение;
- `Отмена` не меняет данные;
- подтверждение сброса восстанавливает стартовое состояние.

## 8. Offline

После загрузки preview временно отключить сеть на устройстве.

Ожидаемый результат: интерфейс показывает offline banner; уже загруженная локальная часть приложения остаётся доступна и не выдаёт offline-режим за работу AI.

## 9. System States

Через Profile открыть `Состояния интерфейса` и проверить вкладки:

- loading;
- empty;
- error;
- offline;
- limit.

Все состояния должны быть явно обозначены как demo. На этом внутреннем экране не должно быть кнопок, которые выглядят рабочими, но ничего не делают.

## 10. Мобильный QA

На iPhone проверить:

- нет горизонтальной прокрутки;
- верхняя часть не залезает под Dynamic Island/notch;
- нижняя навигация учитывает safe area;
- touch targets удобно нажимаются;
- клавиатура не закрывает поле ввода;
- фокус на input/textarea не вызывает нежелательный zoom Safari;
- длинный текст не ломает ширину;
- поворот экрана не ломает layout.

## Что считать ошибкой

- белый/пустой экран;
- npm/Vite error в Run;
- бесконечная загрузка;
- горизонтальный overflow;
- кнопка визуально нажимается, но не выполняет описанное локальное действие;
- demo/mock отображается как настоящий AI/backend;
- demo-вход просит реальные учётные секреты;
- история теряется после обычной перезагрузки;
- удаление или полный сброс происходят без подтверждения;
- нижняя навигация перекрывает composer/клавиатуру.

При обнаружении ошибки достаточно прислать скриншот экрана и, если доступен, скрин Console — Shell не требуется.
