# Server-side Trip Persistence & API V1

**Дата:** 2026-09-09  
**Branch:** `feat/travel-trip-persistence-v1`

## 1. Цель

Перевести Trip persistence для реально аутентифицированного пользователя с browser-only storage на trusted server storage, сохранив текущий `Trip` aggregate, UI repository boundary и Email OTP / Account / Session foundation.

Preview mode намеренно остаётся local-only и не имитирует server persistence.

## 2. API V1

Authenticated same-origin API:

| Method | Path | Semantics |
| --- | --- | --- |
| GET | `/api/trips` | list current account Trips |
| GET | `/api/trips/:id` | get one current-account Trip |
| PUT | `/api/trips/:id` | create/update one current-account Trip |

`DELETE` отсутствует намеренно. Deletion, retention, soft-delete/archive и recovery требуют отдельного product/security решения.

## 3. Authorization contract

Источник account identity — только проверенная server session.

Server rules:

- unauthenticated request → `401`;
- service/auth failure → fail closed;
- payload `ownerScopeId` обязан совпадать с authenticated account;
- foreign ownership → reject;
- path Trip ID обязан совпадать с document ID;
- list/get queries всегда account-scoped;
- одинаковый Trip ID у двух аккаунтов не создаёт collision.

Client-supplied `ownerScopeId` никогда не используется как authorization credential.

## 4. Validation / timestamps

Входящий Trip проходит server runtime validation до persistence.

Server нормализует:

- `ownerScopeId`;
- `createdAt`;
- `updatedAt`.

При update исходный server `createdAt` сохраняется, `updatedAt` обновляется. Request body bounded до отдельного Trip JSON limit.

## 5. Storage model

V1 хранит Trip как aggregate document.

Причины:

1. текущий Travel domain продолжает развиваться;
2. вложенные Plan/Transport/Budget/Legal структуры уже имеют domain contracts;
3. ранняя нормализация увеличила бы migration churn без текущей бизнес-потребности;
4. account/timestamp fields, нужные для authorization/indexing, вынесены отдельно.

### SQLite

`travel_trips`:

- `account_id`;
- `id`;
- `document_json`;
- `created_at`;
- `updated_at`;
- primary key `(account_id, id)`;
- FK → `auth_accounts`.

### PostgreSQL

Тот же logical contract, но `document_json` хранится как `jsonb`.

## 6. Migration strategy

`001_auth_foundation` не изменяется.

Новая migration: `002_travel_trip_persistence`.

- additive only;
- migration checksum registry;
- PostgreSQL advisory transaction lock;
- повторный запуск idempotent по migration ID/checksum;
- никакого `DROP`, удаления данных или irreversible transform.

PR #28 подтвердил на PostgreSQL 18.4 последовательное применение `001_auth_foundation` и `002_travel_trip_persistence`.

## 7. Frontend repository selection

`TravelApp` использует asynchronous repository interface.

- preview → browser/local adapter;
- real-auth account → HTTP adapter;
- HTTP adapter использует `credentials: same-origin`;
- PUT добавляет `X-Arvelis-Request: 1`;
- server error показывается как persistence error;
- заполненная форма не очищается при failed save;
- silent fallback в localStorage запрещён.

## 8. Browser happy-path

Один реальный browser test заменяет множество малополезных UI smokes для этого slice.

Flow:

1. создаётся временная SQLite database;
2. server schema/migrations применяются;
3. создаются test account + HttpOnly-compatible session;
4. поднимается реальный `dev:auth` runtime + Vite same-origin proxy;
5. Chromium запускается в mobile viewport `390×844`;
6. browser получает session cookie;
7. UI создаёт `Казань → Сочи` Trip;
8. Trip сохраняется через `/api/trips` в SQLite;
9. page reload;
10. `Мои поездки` повторно загружает Trip с сервера;
11. Trip открывается повторно;
12. test читает SQLite и подтверждает owner/destination/duration/budget;
13. проверяются page overflow, минимум 44px для видимых controls и отсутствие runtime errors;
14. временная test DB удаляется.

## 10. Security maintenance discovered during slice

CI detected high-severity Nodemailer advisories before Trip tests executed. Nodemailer was upgraded from `9.0.5` to `9.1.1` and lockfile regenerated by npm. Audit затем вернулся к zero vulnerabilities.

Временный self-mutating workflow, использованный только для npm-generated lock, удалён; финальный CI не выполняет commit/push.
