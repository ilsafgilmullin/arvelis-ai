# ARVELIS AI — Chat Experience QA

Основание: реальный iPhone preview после merge PR №8 и глобальная переработка Chat candidate в `feat/chat-experience-v1`.

## Подтверждено текущим runtime main

- Smart Entry работает и персональное приветствие отображается;
- Home использует имя пользователя;
- Chat функционально создаёт и сохраняет локальные сообщения;
- после нормализации на диалог остаётся одно preview-status сообщение;
- реальный AI/backend пока не подключены;
- текущий candidate расширяет именно frontend/local-preview chat UX, а не имитирует AI-функции.

## Цель candidate

Сделать Chat полноценным conversational-модулем ARVELIS AI: быстрым, понятным, дружелюбным и готовым к будущему provider-agnostic AI gateway без повторного переписывания базового UX.

ARVELIS AI сохраняет:

- графитово-золотой бренд;
- утверждённую геометрию логотипа;
- честную маркировку PREVIEW;
- mobile-first навигацию;
- отсутствие фиктивных AI/backend функций.

## Реализуемые frontend/local функции

### Conversation flow

- пользовательское сообщение — компактная правая bubble;
- assistant/mock сообщение — отдельная полноширинная ARVELIS AI зона;
- системный preview-status — компактное notice;
- время сообщения вторично;
- отредактированное пользовательское сообщение получает пометку `изменено`;
- длинный текст использует `overflow-wrap` и не создаёт horizontal overflow.

### Message actions

- `Копировать` реально пишет текст в Clipboard API;
- если Clipboard API недоступен, используется DOM fallback;
- при отказе копирования пользователь получает `Не удалось`, а не ложный success;
- `Изменить` доступно только для пользовательских сообщений;
- system/mock/assistant сообщения не редактируются локальным user-edit action;
- сохранённая правка обновляет локальную модель и `editedAt`.

### Thread actions

- текущий диалог можно переименовать;
- название ограничено 80 символами и нормализует повторные пробелы;
- новое название сохраняется в локальной истории;
- новый диалог доступен из header/sidebar;
- удаление диалога остаётся в History и одновременно удаляет его draft.

### Drafts

- отдельный draft хранится для каждого thread id;
- новый ещё не созданный диалог имеет отдельный draft key;
- draft восстанавливается при возвращении в диалог;
- после отправки draft удаляется;
- полный preview reset очищает drafts;
- draft storage ограничен по количеству и длине;
- если draft нельзя сохранить, Chat показывает явное предупреждение.

### Smart scroll

- при открытии существующего диалога Chat идёт к последнему сообщению;
- после собственного отправленного сообщения Chat остаётся у конца;
- если пользователь вручную читает старую часть истории, будущая добавка не должна насильно утаскивать его вниз;
- в таком состоянии появляется `К последнему`;
- кнопка исчезает рядом с концом ленты;
- поведение готовит UI к будущему streaming response, хотя streaming пока не реализован.

### Empty state / quick starts

- новый диалог показывает спокойный empty-state;
- четыре быстрые заготовки только заполняют composer;
- выбор заготовки НЕ отправляет запрос автоматически;
- заготовка не считается AI-функцией и остаётся локальным UI helper.

### Composer / keyboard

- floating/capsule composer;
- textarea растёт до установленного max-height;
- send disabled для пустого/пробельного текста;
- desktop: Enter отправляет, Shift+Enter создаёт строку;
- coarse/touch device: Return не перехватывается и остаётся новой строкой; отправка кнопкой;
- composer остаётся доступным при iPhone keyboard через существующий `visualViewport` hardening;
- mobile navigation скрывается при focus;
- helper под composer скрывается на mobile;
- счётчик символов появляется только после 80% лимита;
- misleading `+` в composer не показывается, пока attachment action реально не реализован.

### Smart Entry

- loading остаётся scrollable на short-screen/landscape;
- системный scrollbar визуально скрыт без запрета прокрутки.

### Naming

- desktop navigation показывает `ARVELIS AI`, не `Рабочее пространство`.

## Проверка после будущего merge

### Базовый запуск

1. Replit → Git → Pull → Run.
2. Smart Entry: нет видимого scrollbar справа.
3. Home: персональное приветствие и mobile navigation работают.
4. Открыть Chat.

### Новый диалог

5. Нажать `Новый диалог`.
6. Проверить empty-state и четыре quick-start кнопки.
7. Нажать quick-start — текст должен только появиться в composer.
8. Дописать текст и отправить.
9. Должен создаться новый локальный thread и только один preview notice.

### Draft

10. Ввести незавершённый текст, не отправляя.
11. Перейти в History/Home.
12. Вернуться в тот же Chat — draft должен восстановиться.
13. Переключиться на другой thread — его draft независим.
14. Отправить draft — после возвращения он не должен появляться снова.

### Копирование

15. Скопировать user message — кнопка показывает `Скопировано` только после успеха.
16. Скопировать assistant/mock message.
17. При невозможности Clipboard должна появиться ошибка, а не success.

### Редактирование

18. Нажать `Изменить` у user message.
19. Проверить Cancel.
20. Сохранить правку — текст меняется и появляется `изменено`.
21. Обновить страницу — правка должна сохраниться через workspace localStorage.
22. У assistant/system не должно быть user-edit action.

### Переименование

23. Переименовать текущий диалог.
24. Проверить Escape/Отмена.
25. Сохранить новое имя.
26. Открыть History — название должно совпасть.
27. Перезагрузить страницу — название должно сохраниться.

### Scroll

28. Открыть длинный thread — старт у последнего сообщения.
29. Прокрутить вверх достаточно далеко.
30. Должна появиться кнопка `К последнему`.
31. Нажать её — возврат к концу.
32. Отправить сообщение, находясь выше — собственная отправка должна вернуть к новому сообщению.

### Keyboard / mobile

33. iPhone: открыть keyboard.
34. Mobile nav скрывается, composer остаётся доступным.
35. Return добавляет новую строку, а не отправляет сообщение.
36. Отправка выполняется кнопкой.
37. Закрыть keyboard — mobile nav возвращается.
38. Проверить 320–360 px и landscape при возможности.

### Long content / limit

39. Вставить длинную строку/URL — нет horizontal overflow.
40. После 4 800 символов появляется counter.
41. После 6 000 символов дальнейший ввод ограничивается.

### Desktop

42. Sidebar показывает `ARVELIS AI`.
43. Desktop Enter отправляет сообщение.
44. Shift+Enter создаёт новую строку.
45. Message actions доступны по hover/focus, но не перегружают ленту постоянно.

## Вне scope / не выдавать за реализованное

- реальные AI-ответы;
- streaming tokens;
- `Stop generation`;
- `Regenerate`;
- attachment/file upload;
- камера;
- voice input/output;
- web search;
- citations;
- model selector;
- server sync;
- backend/auth;
- изменение утверждённого логотипа или базовой цветовой системы.

Эти возможности требуют отдельных продуктовых решений и реальной backend/provider реализации. Candidate не показывает их как доступные функции.
