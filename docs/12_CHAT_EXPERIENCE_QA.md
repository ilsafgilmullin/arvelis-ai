# ARVELIS AI — Chat Experience QA

Основание: реальный iPhone preview после merge PR №8 и глобальная переработка Chat candidate в `feat/chat-experience-v1`.

## Подтверждено текущим runtime main

- Smart Entry работает и персональное приветствие отображается;
- Home использует имя пользователя;
- Chat функционально создаёт и сохраняет локальные сообщения;
- после нормализации на диалог остаётся одно preview-status сообщение;
- реальный AI/backend пока не подключены;
- текущий candidate расширяет именно frontend/local-preview Chat UX, а не имитирует AI-функции.

## Цель candidate

Сделать Chat полноценным conversational-модулем ARVELIS AI: быстрым, понятным, дружелюбным и готовым к будущему provider-agnostic AI gateway без повторного переписывания базового UX.

ARVELIS AI сохраняет:

- графитово-золотой бренд;
- утверждённую геометрию логотипа;
- честную маркировку PREVIEW;
- mobile-first навигацию;
- отсутствие фиктивных AI/backend функций.

## Реализуемые frontend/local функции

### Conversation flow

- пользовательское сообщение — компактная правая bubble;
- assistant/mock сообщение — отдельная полноширинная ARVELIS AI зона;
- системный preview-status — компактное notice;
- время сообщения вторично;
- отредактированное пользовательское сообщение получает пометку `изменено`;
- длинный текст использует безопасный wrapping и не создаёт horizontal overflow;
- длинная история разделяется по датам (`Сегодня`, `Вчера`, локализованная дата).

### Message actions

- `Копировать` реально пишет текст в Clipboard API;
- если Clipboard API недоступен, используется DOM fallback;
- при отказе копирования пользователь получает `Не удалось`, а не ложный success;
- copy-result дополнительно объявляется через `aria-live`;
- `Изменить` доступно только для пользовательских сообщений;
- system/mock/assistant сообщения не редактируются локальным user-edit action;
- сохранённая правка обновляет локальную модель и `editedAt`.

### Thread actions

- текущий диалог можно переименовать;
- название ограничено domain policy и нормализует повторные пробелы;
- новое название сохраняется в локальной истории;
- текущий диалог можно удалить прямо из Chat через ConfirmDialog;
- удаление очищает draft удаляемого thread;
- после удаления активного thread открывается чистое состояние нового диалога;
- новый диалог доступен из header/sidebar.

### Drafts

- отдельный draft хранится для каждого thread id;
- новый ещё не созданный диалог имеет общий draft key для Home и пустого Chat;
- текст, начатый на Home, должен продолжаться в Chat и наоборот;
- draft восстанавливается при возвращении в существующий диалог;
- после отправки draft удаляется;
- полный preview reset очищает drafts;
- draft storage ограничен по количеству и длине;
- если draft нельзя сохранить, Home/Chat показывают явное предупреждение.

### Local search

- поиск выполняется только внутри текущего локального thread;
- поиск сравнивает обычный текст сообщений и не использует `innerHTML`;
- показывается количество совпадений и текущая позиция;
- `Далее` / `Назад` переходят циклически между совпадениями;
- Enter/Shift+Enter в search input переходят вперёд/назад;
- Escape закрывает поиск;
- активное совпадение прокручивается к центру и получает ненавязчивый visual state;
- поиск, rename и delete не должны наслаиваться друг на друга.

### Smart scroll

- при открытии существующего диалога Chat идёт к последнему сообщению;
- после собственного отправленного сообщения Chat остаётся у конца;
- если пользователь вручную читает старую часть истории, будущая добавка не должна насильно утаскивать его вниз;
- в таком состоянии появляется `К последнему`;
- кнопка исчезает рядом с концом ленты;
- поведение готовит UI к будущему streaming response, хотя streaming пока не реализован.

### Empty state / quick starts

- новый диалог показывает спокойный empty-state;
- четыре быстрые заготовки в Chat только заполняют composer;
- быстрые сценарии на Home также только заполняют общий new-chat draft;
- выбор заготовки НЕ отправляет запрос автоматически;
- заготовка не считается AI-функцией и остаётся локальным UI helper.

### Composer / keyboard

- floating/capsule composer;
- textarea растёт до установленного max-height;
- send disabled для пустого/пробельного текста;
- desktop: Enter отправляет, Shift+Enter создаёт строку;
- coarse/touch device: Return не перехватывается и остаётся новой строкой; отправка кнопкой;
- composer остаётся доступным при iPhone keyboard через существующий `visualViewport` hardening;
- mobile navigation скрывается при focus;
- helper под composer скрывается на mobile;
- счётчик символов появляется только после 80% лимита;
- misleading `+` в composer не показывается, пока attachment action реально не реализован.

### Preview limits

- новый thread не создаётся после локального preview-лимита threads;
- Home и пустой Chat объясняют, что для нового диалога нужно удалить старый;
- после локального message-limit текущий composer блокируется и предлагает начать новый диалог;
- эти ограничения не выдаются за production/tariff limits.

### Smart Entry

- loading остаётся scrollable на short-screen/landscape;
- системный scrollbar визуально скрыт без запрета прокрутки.

### Naming

- desktop navigation показывает `ARVELIS AI`, не `Рабочее пространство`.

## Проверка после будущего merge

### Базовый запуск

1. Replit → Git → Pull → Run.
2. Smart Entry: нет видимого scrollbar справа.
3. Home: персональное приветствие и mobile navigation работают.
4. Открыть Chat.

### Home → Chat shared draft

5. На Home начать писать задачу, не отправляя.
6. Перейти в Chat → `Новый диалог`.
7. Тот же draft должен быть в composer.
8. Изменить его в Chat, вернуться Home — обновлённый текст должен сохраниться.
9. На Home нажать быстрый сценарий — текст только подставляется в поле и НЕ создаёт thread автоматически.
10. Отправить общий draft — после создания thread `thread:new` draft больше не должен возвращаться.

### Новый диалог

11. Нажать `Новый диалог`.
12. Проверить empty-state и четыре quick-start кнопки.
13. Нажать quick-start — текст только появляется в composer.
14. Дописать текст и отправить.
15. Должен создаться новый локальный thread и только один preview notice.

### Draft существующего thread

16. Ввести незавершённый текст, не отправляя.
17. Перейти в History/Home.
18. Вернуться в тот же thread — draft должен восстановиться.
19. Переключиться на другой thread — его draft независим.
20. Отправить draft — после возвращения он не должен появляться снова.

### Копирование

21. Скопировать user message — кнопка показывает `Скопировано` только после успеха.
22. Скопировать assistant/mock message.
23. При невозможности Clipboard должна появиться ошибка, а не success.
24. VoiceOver/aria-live не должен объявлять успех до реального результата copy.

### Редактирование

25. Нажать `Изменить` у user message.
26. Проверить Cancel.
27. Сохранить правку — текст меняется и появляется `изменено`.
28. Обновить страницу — правка должна сохраниться через workspace localStorage.
29. У assistant/system не должно быть user-edit action.
30. Пустую правку сохранить нельзя.

### Переименование

31. Переименовать текущий диалог.
32. Проверить Escape/Отмена.
33. Сохранить новое имя.
34. Открыть History — название должно совпасть.
35. Перезагрузить страницу — название должно сохраниться.
36. Очень длинное название не должно ломать Topbar; используется ellipsis.

### Удаление текущего диалога

37. Нажать delete в Chat header.
38. ConfirmDialog должен получить фокус и корректно закрываться Escape/Отмена.
39. Подтвердить удаление.
40. Удалённый thread исчезает из History, его draft очищается, Chat становится новым пустым диалогом.

### Поиск по текущему диалогу

41. Открыть thread с несколькими сообщениями и включить Search.
42. Ввести часть текста user/assistant/system message.
43. Проверить `1 / N`, `Далее`, `Назад` и циклический переход.
44. Enter переходит к следующему совпадению, Shift+Enter — к предыдущему.
45. Escape закрывает поиск.
46. Запрос без совпадений показывает `0 / 0` и не ломает прокрутку.
47. Открытие Rename/Delete закрывает search UI, панели не накладываются.
48. В тексте с `<`, `>`, URL и спецсимволами поиск не должен интерпретировать пользовательский текст как HTML.

### Даты

49. В длинной истории проверить разделители `Сегодня` / `Вчера` / дату.
50. Разделитель появляется только при смене календарного дня, а не перед каждым сообщением.

### Scroll

51. Открыть длинный thread — старт у последнего сообщения.
52. Прокрутить вверх достаточно далеко.
53. Должна появиться кнопка `К последнему`.
54. Нажать её — возврат к концу.
55. Отправить сообщение, находясь выше — собственная отправка должна вернуть к новому сообщению.
56. Переход по Search match не должен автоматически отбрасываться к низу.

### Keyboard / mobile

57. iPhone: открыть keyboard.
58. Mobile nav скрывается, composer остаётся доступным.
59. Return добавляет новую строку, а не отправляет сообщение.
60. Отправка выполняется кнопкой.
61. Закрыть keyboard — mobile nav возвращается.
62. Проверить Search input, Rename input и message editor с iPhone keyboard.
63. Проверить 320–360 px и landscape при возможности.

### Long content / limit

64. Вставить длинную строку/URL — нет horizontal overflow.
65. После 4 800 символов появляется counter.
66. После 6 000 символов дальнейший ввод ограничивается.
67. Проверить локальный thread limit: создание нового thread блокируется с понятным сообщением.
68. Проверить local message limit: composer блокируется и предлагает новый диалог.

### Desktop

69. Sidebar показывает `ARVELIS AI`.
70. Desktop Enter отправляет сообщение.
71. Shift+Enter создаёт новую строку.
72. Message actions доступны по hover/focus, но не перегружают ленту постоянно.
73. Search/rename/delete/new-chat header actions доступны с клавиатуры.

## Вне scope / не выдавать за реализованное

- реальные AI-ответы;
- streaming tokens;
- `Stop generation`;
- `Regenerate`;
- attachment/file upload;
- камера;
- voice input/output;
- web search;
- citations;
- model selector;
- server sync;
- backend/auth;
- изменение утверждённого логотипа или базовой цветовой системы.

Эти возможности требуют отдельных продуктовых решений и реальной backend/provider реализации. Candidate не показывает их как доступные функции.
